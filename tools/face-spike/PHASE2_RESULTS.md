### 全体クラスタリングの方式（§5.6 の実装確定）

- 単位は (動画, 動画内グループ)。代表埋め込みの品質降順に leader-follower で割り当てる
- 割当て条件: 対象人物の**代表埋め込みと重心の両方**に類似度 ≥ T_global（= 0.50、D5）が必要で、スコア = min(代表類似度, 重心類似度) が最大の人物に割り当てる。重心は (動画,グループ) の顔数で重み付けした代表埋め込みの平均（正規化）。片方だけの条件では Phase 0 で実測した重心ドリフト混入（T=0.35〜0.45 で Norton が Unknown B のクラスタに吸収）が起きるため、両方要求が対策になる
- 重心の更新は割当てのたびに行う

### 人物 ID の安定化方式

- 再分類のたびに、新クラスタと旧 PersonRecord を**代表埋め込み同士の類似度**で対応付ける（類似度 ≥ T_global のペアを降順に貪欲に 1 対 1 マッチ）。設計書の「代表 faceId が一致すれば引き継ぐ」は類似度 1.0 のケースとして包含される（代表顔が再スキャンで差し替わっても、埋め込みが近ければ引き継げる）
- 引き継ぐもの: personId、名前（name）、非表示フラグ（hidden）。属性集約は**グループ集合が完全一致する場合のみ**引き継ぎ、変わっていれば属性パスで再計算されるまで付けない（古い集約を別構成の人物に表示しない）
- 新規人物の ID は単調増加の連番（`nextPersonSeq`、index に保存）で採番し、**消えた人物の ID は再利用しない**。古い .vha2 キャッシュが別人を指す事故を防ぐため

### 属性推定の入力経路（実測で決定）

- 設計の基準経路（元フレーム＋bbox 切り抜き）と、保存済み aligned 112×112 を入力にする経路を Phase 0 の 63 顔で比較実測した:
  - aligned を 96×96 にリサイズして入力: 性別一致 **55/63**、年齢差の中央値 **9 年**（最大 30）
  - aligned 上に名目 bbox を置いて基準の切り抜き処理を適用: 性別一致 **55/63**、年齢差の中央値 **7 年**（最大 23）
  - いずれも基準経路（フレーム再抽出）に対して明確に劣化するため不採用
- 採用方式: 属性ジョブ（worker）がサンプル顔のフレームを**その場で再抽出**し、基準経路で推論する。サンプルは (動画,グループ) ごとに品質上位 5 顔（`attributeSamplesPerGroup`）までなので、再抽出は最大でも数十フレーム/回で収まる
- 推論は再分類時に実行（自動再分類＝スキャン drain 後、手動再分類、属性オンへの切替時）。オフ時は集約処理自体が走らず、既存の集約値も再分類時に消去する
- 顔ごとの推定値は worker のメモリ内でのみ存在し、**index.json 等に一切保存しない**（設計書 §6.2 の任意 `attr` フィールドは実装しないことに確定し、設計書側も訂正済み）
- 動画ファイルのパスが判明している動画だけが属性の対象（main プロセスはスキャンした動画と renderer から渡された要素のパスを保持する。パス不明の (動画,グループ) はサンプルから外れる）

### .vha2 キャッシュの書戻し経路（D4 決定済み）

- 正は faces/index.json。main が payload に `personsByVideo`（hash → personId 配列）を載せ、renderer の FaceService が受信のたびに全 ImageElement の `persons` と照合して差分を書き込む。差分があれば `finalArrayNeedsSaving = true` にし、**保存自体は既存の保存フロー**（ハブを閉じる/切り替える際の getFinalObjectForSaving）に乗る（顔機能専用の保存経路は作らない）
- faces/ を消した場合は index が無効になり personsByVideo が空で返るため、全要素のキャッシュが除去され dirty 化する（再スキャンで是正される設計どおり）。モデル不一致時も同様に空になる

### Angular UI（§8.2）

- サイドバー人物欄: 代表顔の丸サムネイル＋名前＋登場動画数、上位 10 件、クリックで人物フィルタ（再クリックで解除）、「すべて見る」で人物一覧モーダル。表示トグルはグローバル設定ボタン `showPersonsSidebar`（§7 の指定どおり、設定の顔セクションから切替）
- 人物フィルタ: `person-filter.pipe` をギャラリーの pipe チェーンに追加（既存フィルタと AND）。フィルタは要素の `persons` キャッシュで判定し、index 更新のたびに FaceService の版数カウンタで再評価する
- 人物一覧ビュー（`app-persons` コンポーネント、モーダル）: 人物カードのグリッド（代表顔・名前・動画数/顔数・属性集約・非表示切替）。名前はインライン編集（クリック→入力→Enter/blur で IPC 保存）。再分類ボタンと属性再計算ボタン、空状態（「まだ顔スキャンされていません」相当＋スキャンボタン）を持つ。**結合・分割・顔の付け替え・代表顔の変更は Phase 3 のため実装していない**
- 動画詳細の顔ストリップに人物名チップを追加（未命名は「人物 N」）。クリックで人物フィルタ（meta → details / 下部トレイ → home へ伝播）
- 設定の顔セクション追加分: 属性トグル＋注記（集約のみ保存・±10 年級の推定である旨）、genderage 配置状態の表示、全体クラスタリング閾値の数値入力、再分類ボタン、統計への人物数追加。閾値変更・属性切替時は home が自動で再分類を要求する
- i18n は en.json のみ追加（他言語は後からでよいという設計 §8 の注記どおり）
- 人物の並び順は §8.1 どおり「登場動画数の多い順」

## 検証中に発見・修正したバグ（Phase 1 由来を含む）

1. **display crop が真っ黒**（`5e83969`、Phase 1 のバグ）: `displayCrop` の切り抜き幅・高さが float のまま画素インデックス計算に使われ、非整数インデックスへの TypedArray 書込みが全て無視され、crop が全面ゼロになっていた。実アプリでも代表顔画像が全て黒く表示される状態だった。Phase 1 のハーネスは枚数のみ確認しており見逃した。ジオメトリを整数化して修正し、Phase 2 ハーネスに「crop が黒でないこと」の検査を追加（修正後は 29/29 件が正常な内容）
2. **grabFrameImage の上書きプロンプト停止**（`ca5d5f6`）: ffmpeg 引数（generateFaceFrameArgs）に `-y` がなく、出力先に同名ファイルがあると上書き確認で停止する。属性パスが同じ出力パスを再利用する使い方で顕在化した。抽出前に出力先を消去し、失敗時に旧ファイルを誤ってデコードしないよう修正

### 全体クラスタリング（T = 0.50）

- 人物数: **24**（Phase 0 の T=0.50 は 18）
- **動画をまたぐ 3 組の統合を確認**: Davies（yuXG + V9Dq の 2 グループが同一人物に）、Gosling（同）、Attenborough 高齢期（z0B4 + Gfa88 の 2 グループが同一人物に）。いずれも Phase 0 の T=0.50 クラスタと対応
- **混入なし**: Phase 0 の確定ラベル（tentative を除く）で、異なる 2 名が 1 人物に混ざったケースは 0 件。Phase 0 で T=0.35〜0.45 にあった重心ドリフト混入（Norton ↔ Unknown B）も再現しなかった
  - 補足: アプリの Norton 人物には「Unknown B（tentative ラベル）の Phase 0 グループに最も近いアプリグループ」が 1 件含まれるが、目視確認ではそのグループの代表顔は **2016 年放送回の髭のない Norton 本人**だった（Phase 0 の dmbp には Norton のグループ自体が存在しないため、転移先が最も近い別人になった＝ラベル転移側の人工物）。この人物の 4 グループ間の代表類似度は最小でも 0.517 で内的にも整合し、属性の年齢中央値 53 も 2016 年当時の Norton の実年齢（51 歳）から大きく外れておらず、この人物が Norton 本人である傍証になっている（属性の詳細は後述。性別 M で一致、一致率 1.00、サンプル 5 件）

（注: 本節の後半以降は、記録ファイル末尾の欠落を補完するため、2026-10-24 に `phase2-harness.cjs` を再実行して再計測した値に基づく。再実行でも全チェック合格し、人物数 24、Norton 人物の年齢中央値 53 など、残存していた記述の数値と一致した）

- **人物数 24 と Phase 0 の 18 の差の内訳**: 人物数 = グループ数 − 統合（join）件数で分解できる。アプリは 29 グループ − 5 件の統合 = 24、Phase 0 は 21 グループ − 3 件の統合 = 18 で、差 +6 は「グループ +8」と「統合 +2」の合計である
  - グループ +8 の動画別内訳（アプリ vs Phase 0）: yuXG 8 vs 5、dmbp 7 vs 6、V9Dq 2 vs 3、8cPx 4 vs 2、z0B4 7 vs 3、Gfa88 1 vs 2。原因は Phase 1 スキャンのサンプリング位置の設計差（§5.1 の区間中点サンプリング vs Phase 0 の [2%, 98%] 方式）で、アプリ側が Phase 0 の写っていない顔を追加で拾った
  - 統合 +2 の内訳: アプリの統合は Davies（2 グループ → 1 人物）、Attenborough 高齢期（2 グループ → 1 人物）、Norton（4 グループ → 1 人物 = 3 件の統合）。Norton は Phase 0 では 8cPx の単独グループしかなく動画間統合の対象にならなかった分が +3 件。逆に Gosling はアプリでは yuXG 内の主グループ＋劣化断片の 2 人物のまま（下記）で、Phase 0 の統合分から −1 件
  - **未転移グループのみで構成される人物が 12 件**（24 件中）。ラベル転移が一致したのは 29 グループ中 15 件（類似度 ≥ 0.45）で、残りは Phase 0 に写っていない顔のグループである。12 件中 11 件が 1 顔のみのグループで、代表顔の目視による内訳は次のとおり: 深海魚映像への誤検出 1 件（z0B4、人物ではない）、アーカイブ映像の低品質・ブレ顔 4 件（z0B4）、8cPx のゲストの端の顔 2 件、上向きに笑う Crowe の別角度 1 件、手で顔を覆った遮蔽顔 2 件（うち 1 件は手で顔を覆って笑う Cleese で、主人物とは統合されなかった遮蔽断片）、ワイドショットや横顔のブレ顔 2 件。いずれも「Phase 0 と違う顔を拾った」ことによる増分であり、混入ではない
  - Phase 0 の分割構造の再現: Gosling は主クラスタ (p000011) ＋劣化断片 (p000013) の 2 人物、Attenborough は高齢期の統合人物 (p000001) ＋若年期アーカイブの断片 (p000008、白黒映像の若い Attenborough) の 2 人物になり、Phase 0 の T=0.50 と同じ分割になった。Cleese は Phase 0 では 2 人物に分割されたが、アプリでは主グループが 1 件のみ検出されたため主人物は 1 件のみ（遮蔽断片は上記の別人物として残る）

### 属性集約（genderage、§5.8）

ハーネスでは worker の基準経路（フレーム再抽出）で全人物の集約を計算し、Phase 0 の集約値（cluster-test/attrs_T0.50.json）と照合した。

- 集約を計算できた人物: **24 件全件**。保存後の index.json でも 24 件全件に人物単位の集約が載ることを確認した
- **性別: ラベル既知の 11 人物レコードすべてで既知の性別と一致（11/11）**。性別一致率はいずれも 1.00。実在人物としては 9 名分である（Attenborough と Gosling は分割により 2 レコードずつ現れる）
- 年齢中央値の Phase 0 との比較（同一人物として対応付けできるもののみ）: Attenborough（高齢期）74 vs 75（差 1、サンプル 10）、Mack 46 vs 46（差 0）、Davies 50 vs 59（差 9、サンプル 10）、Whittaker 28 vs 25（差 3）、Farrell 64 vs 65（差 1）、Attenborough（若年期断片）51 vs 51（差 0、サンプル 1）、Crowe 45 vs 46（差 1）、Gosling（主）36 vs 32（差 4）、Gosling（断片）40 vs 37（差 3、サンプル 1）、Cleese 59 vs 67（差 8、サンプル 1）。最大差は Davies の 9 年で、ハーネスの合格条件（15 年以内）を全件満たした。差の主因はサンプリング位置の違いによるサンプル顔の相違であり、Phase 0 の集約自体が実年齢に対して ±10 歳級の誤差を持つ推定であるため、この照合は「パイプラインが同等の集約を返す」ことの確認であって、精度の保証ではない
- Norton 人物 (p000007) は性別 M で一致（年齢中央値 53）。ただし構成グループが Phase 0 の複数人物（tentative 含む）にまたがるため Phase 0 側の対応集約がなく、年齢比較は対象外とした
- **顔ごとの属性値が保存物に残らないこと**: 保存後の index.json 全文に `"attr"` キーが存在しないこと、全顔レコードに attr / age / sex フィールドがないことを確認した（設計 §5.8 の「保存は集約のみ」を満たす）
- 属性オフ相当の消去: 集約をクリアすると全人物から attributes が除かれることを確認した

### 人物 ID の安定化

- 検証方法: ハーネス内で Davies 人物 (p000003) に名前「Greg Davies」を付け、そのまま再分類（clusterizeIndex → applyClustering）を実行し、保存し直して再読込した
- 結果: **名前を付けた人物は再分類後も同じ personId (p000003) で名前を保持**し、全 72 顔の顔 → 人物割当てが再分類前と完全一致した。clusterize を再実行しても人物 ID の並びが同一になること（決定性）も確認した
- 検証範囲の限界: 確認したのは同一の顔集合に対する再分類のみ。再スキャンで顔集合が変わる場合と、閾値を変更した場合の継承挙動は未検証（Phase 3 への引き継ぎに記載）

### .vha2 キャッシュ（personsByVideo）の整合

- ハーネスでは、キャッシュの導出元である personsByVideo と index の persons を突き合わせた: **全 24 人物について、その人物の videoHashes 全件が personsByVideo[hash] に含まれている**ことを確認した。Davies 人物が yuXG と V9Dq の両方に現れることも確認した
- 未検証の範囲: renderer 側の書戻し（FaceService が ImageElement.persons へ書き込む処理）と、既存の保存フローに乗った実際の .vha2 ファイルへの保存・再読込は、実アプリ（Electron + renderer）を動かす必要があるため本ハーネスでは確認していない（未確認事項に記載）
